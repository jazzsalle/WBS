# SOT v4.9 설계 요약 — 수행 모드 = 협약 예산 (2026-09-29 사용자 지시)

> 이 문서는 SOT 개정 **전** 합의용 요약이다. 승인되면 Phase 23 T0이 SOT 본문(§5·§6.4·§6.14·§7.9·§8.7·§8.8·§9·§11)에 옮기고, 이 문서는 근거 기록으로 남긴다.

## 1. 사용자 지시 원문 요지
1. 조정회의 예산 검토용 양식 추가 — 예산을 넣으면 자동 계산
2. 붙임4 과제별 사업비검토양식 추가 — 자동 계산
3. 전담기관 간사 지침 반영. **집행내역 관리는 필요 없다**(RCMS·경영관리팀·정산 시스템 몫). 과제관리팀은 **리스크 관리**에 집중
4. 제안 = 편성 규칙 준수 체크. 수행 = 협약 시 수정 사업비 기록 + 연구 중 참고 + **협약변경 관리**(참여인원·인건비·기타 사업비 수정 기록과 이력)
5. 수행 내용은 엑셀 내려받기 또는 [복사](엑셀에 그대로 붙여넣기)
6. 수행도 연구비 규칙 준수를 관리

## 2. 확정된 결정 (대화 2026-09-29)
- D-1 **집행 관리 기능 완전 삭제**: 집행 등록·집행 내역·집행률·Phase 20 수행 양식(IN-9~IN-14)·대시보드/개요의 집행률
- D-2 **기관 구분 없음**: 제안·수행 모두 우리 기관 예산만 다룬다(컨소시엄 타 기관 금액은 관리하지 않는다)
- D-3 **수행 모드 전용 새 구조**: 제안 모드 데이터(budget_items·budget_details)는 그대로 둔다
- D-4 수행 모드는 **하나의 데이터를 여러 보기(타입)로** 본다 — 비목별·붙임4형·조정회의형. 어느 보기에서 고쳐도 같은 데이터
- D-5 **붙임4 엑셀 가져오기**: 8-2 사용계획의 **우리 기관 블록**만 읽어 버전을 만든다. 8-1은 금액 정합 확인용
- D-6 **제안 → 수행**: 제안 편성을 마치면 [협약 기준선으로 보내기]로 첫 버전을 만들고, 이후 두 모드는 독립
- D-7 조정회의형 보기는 **현재 버전 하나**를 보여 준다(변경 전/후 비교 화면이 아니다 — 샘플의 전/후는 양식 예시)
- D-9 **과제 유형은 과제마다 다르다** — 과제 개요 화면에서 입력(원천기술형·혁신제품형·실증형·안전관리형 등). **우리 회사는 중소기업**으로 고정(기업 유형 입력 칸 없음 — 비율 판정은 중소기업 값)
- D-10 **규칙은 제안 모드 연구비 규칙(§6.14·budget_rules)을 그대로 쓴다** — 수행 모드도 같은 규칙 집합으로 현재 버전을 판정. 간사 지침에서 나왔는데 제안 모드에 없던 규칙은 **추가해서 제안·수행 두 곳에** 적용
- D-11 영리기관 인건비 현금 인정 조건은 **넣지 않는다**(중소기업이라 당연히 해당)
- D-12 세목 총액 보존·정부출연금/민간현금 비율은 **경고**로
- D-13 버전: 확정 버전은 잠금, 작성 중 버전은 1개. **어떤 버전이든 삭제 가능 + 전체 버전 일괄 삭제**(확인 대화)
- D-14 세목 총액 보존 기준 = 최종협약본(없으면 직전 확정 버전)
- D-15 참여인원은 과제 인력에서 고르고 인건비 = 월급 × 참여율 × 개월 자동 계산(수동 수정 허용)
- D-16 붙임4는 **양식일 뿐** — 우리 회사 블록만 있으면 된다(파일에 수행기관 블록이 하나면 그것, 여럿이면 우리 회사 이름과 일치하는 블록)
- D-8 건별 금액 기준: **장비 3천만 원(부가세 포함)**·재료 단일품목 2천만 원·외주용역 3천만 원, 3천만 원 근접 동일·유사 외주 여러 건은 "검토 필요". **증빙 체크리스트까지** 둔다(파일 첨부 없음 — 확보 여부 체크)

## 3. 개념

### 3.1 협약 예산 버전 (Agreement Version)
과제마다 버전이 순서대로 쌓인다: `선정평가본` → `조정회의본` → `최종협약본` → `협약변경 1차` → `2차` …
- 새 버전은 **직전 버전을 복제**해서 만들고 바뀐 곳만 고친다(첫 버전은 제안 모드에서 보내기 또는 붙임4 가져오기 또는 빈 버전)
- 버전 메타: 종류, 이름, 기준일, 변경 사유, 통보/승인 구분, 공문 번호, IRIS 신청일·승인일, 비고
- **확정**(잠금): 확정된 버전은 고칠 수 없다(이력 보존). 확정 전(작성 중) 버전은 하나만 둘 수 있다 — *초안 제안, 확인 필요*
- "현재 버전" = 확정된 버전 중 가장 최근 것. 작성 중인 버전이 있으면 화면에서 전환해 본다

### 3.2 버전에 담기는 것
| 구분 | 내용 |
|---|---|
| 금액 줄 | 연차 × 비목·세목(부록 A.5 세목) × 현금/현물 → 금액(원 단위 정수) |
| 참여인원 | 인력(과제 Member 연결)별 연차 참여율·참여 개월·인건비 현금/현물·역할 — 협약변경으로 바뀐 참여인원·인건비 기록(요청 4) |
| 편성 항목 | 장비·재료·외주 건별: 연차, 품명, 금액(장비는 부가세 포함), 수량, 증빙 체크리스트(견적서·비교견적서·과업지시서·계약서·중간산출물 등 항목별 확보 여부·메모) |
| 메타 | 3.1 |

### 3.3 보기 (같은 버전을 여러 모양으로)
1. **비목별** — 지금 제안 모드와 같은 연차 × 비목 매트릭스(현금/현물), 셀 편집
2. **붙임4형** — 8-1 지원·부담계획(우리 기관 한 줄: 정부지원 현금, 기관부담 현금·현물, 비율, 정부출연금비율·민간현금비율 판정) + 8-2 사용계획(세목 × 현금/현물 × 연차, 총 인건비 E1, 수정인건비 E2, 인건비 비율, 연구수당 비율 I/E2, 직접비 소계, 간접비, 간접비 비율, 총액, 검토사항 문구)
3. **조정회의형** — 인건비 A · 연구수당 B · 간접비 C · 합계 D · 총액 E · 직접비 F × 연차 + D/E · B/A · A/F
4. **참여인원** — 인력 × 연차 참여율·개월·인건비 현금/현물
5. **편성 항목·증빙** — 건별 목록, 임계 경고, 체크리스트
6. **변경 이력** — 버전 목록, 두 버전 간 증감(연차·세목·참여인원), 세목 총액 보존 검증

각 보기: [엑셀 내려받기](부록 F 서식, 수식 포함) · [복사](TSV — 엑셀에 붙이면 같은 표)

### 3.4 규칙 검증 — 제안·수행 공통 (요청 6·3, D-10)
**같은 규칙 집합(§6.14 RL-*, 과제별 budget_rules)**을 제안 모드는 산출근거에, 수행 모드는 현재 버전에 적용한다. 이미 있는 것: 연구수당 20% 상한·10% 권고(RL-4·5), 간접비 10%(RL-3), 위탁 40%, 외부전문기술 40%, 정부지원 비율(RL-8), 기관부담 현금(RL-9), 참여율 10%(RL-16), 장비 3천·재료 2천·외주 3천(RL-17~19) 등.
**간사 지침에서 새로 추가(두 모드 모두)**:
- 정부출연금 비율 상한·민간현금 비율 하한을 **과제 유형(D-9) × 중소기업**으로 자동 결정(RL-8·RL-9 값의 출처를 과제 유형으로 — 붙임4 8-1 검토 식), 경고
- 외주 3천만 원 **근접 동일·유사 여러 건** → "검토 필요"(새 규칙)
- 간접비 중 **연구실 안전관리비** = 인건비 + 학생인건비의 1~2%(새 규칙, 해당 세목이 있을 때)
- 장비 기준 금액은 **부가세 포함**(RL-17 문구·입력 안내 정정)
**수행 전용**: 연차 간 이동 시 **세목별 총액 보존**(D-14 기준 버전 대비, 경고). 버전이 있어야 판정 가능하므로 제안 모드에는 없다.
넣지 않는 것: 영리기관 인건비 현금 인정 조건(D-11).
RL-1 원칙 유지: 전부 경고(저장을 막지 않는다).

### 3.5 과제·기관 정보 추가
- 과제: **과제 유형**(원천기술형·혁신제품형·실증형·안전관리형 등 — 붙임4 헤더의 유형 칸) — **과제 개요 화면에서 입력**(D-9). 비율 판정에 쓴다
- 기업 유형은 두지 않는다 — 우리 회사는 중소기업(고정)
