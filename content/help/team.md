# 인력·기관
> 언제 쓰나: 컨소시엄 기관과 참여인력을 등록하고, 역할·연봉·활성 여부를 관리할 때 씁니다.

## 할 수 있는 것
- **기관 섹션**: `기관 추가`로 기관명·역할(주관/공동/위탁)·유형·책임자·담당 연구개발 내용·배분 연구개발비를 등록합니다. 주관기관 카드는 맨 위에 고정됩니다 (SOT §7.10).
- 다른 기관을 `주관으로 지정`하면 기존 주관기관은 자동으로 공동으로 내려갑니다. 주관기관은 과제당 정확히 하나입니다 (SOT §6.6 H-8).
- **인력 섹션**: 기관별로 묶인 표에 이름 / 역할(총괄책임자·책임자·연구원·지원) / 직급 / 분야 / 연락처 / 활성 / 연봉 / 채용구분이 보입니다. `인력 추가`로 직접 등록합니다.
- 채용구분이 `채용예정`이면 배지로 구분됩니다. 아직 사람이 정해지지 않은 자리도 인력으로 등록해야 인건비 산출근거에 올릴 수 있습니다 (SOT §5.11).
- 인력 행을 누르면 그 사람에게 배정된 작업 목록이 옆 패널에 나옵니다.
- `사내 명부에서 추가`: 이름·이메일로 검색해 여러 명을 고르고 `N명 추가`를 누릅니다. 채워지는 것은 **이름·직위·이메일**뿐입니다 (SOT §6.13 HR-4). 외부 기관 인력은 명부에 없으므로 `인력 추가`로 넣습니다.
- 참여가 끝난 사람은 삭제 대신 `비활성`으로 두는 것을 권장합니다 (SOT §6.6 H-9).

## 자주 하는 실수
- 사내 명부로 추가한 인력은 **연봉이 비어 있습니다.** 명부에 급여 정보가 없기 때문입니다. 인건비 산출근거를 쓰려면 연봉을 직접 채워야 합니다 (SOT §6.13 HR-2).
- 명부에서 `이미 등록됨`으로 회색 처리된 사람은 같은 이메일의 인력이 이 과제에 이미 있는 것입니다. 기존 인력은 덮어쓰지 않습니다 (SOT §6.13 HR-8). `이메일 없음`인 사람도 가져올 수 없습니다 (HR-9).
- 명부의 `퇴사` 배지는 표시일 뿐이고 선택을 막지 않습니다. 우리 쪽 `활성`도 자동으로 바뀌지 않습니다 — 퇴사와 과제 참여 종료는 다른 뜻입니다 (SOT §6.13 HR-5).
- 명부 대신 "설정에서 HR API 키를 등록하세요"가 보이면 설정 화면에서 자기 키를 넣어야 합니다. 키는 사용자마다 자기 것을 쓰고 이 PC의 OS 키체인에만 저장되므로 **PC마다 다시 등록**해야 하며 백업 파일에도 들어가지 않습니다 (SOT §6.13 HR-10~HR-12).
- 연봉을 고쳐 저장하면 영향받는 인건비 산출근거 건수와 연차별 전후 금액이 먼저 보입니다. 확인해야 저장되고 예산이 다시 계산됩니다. 영향이 0건이면 바로 저장됩니다 (SOT §6.10 PL-10b).
- 인건비 산출근거가 걸린 인력은 삭제할 수 없습니다. 삭제 대화상자에 산출근거 건수가 따로 표시되고 `연구비로 이동`으로 먼저 정리해야 합니다. `비활성`은 그대로 됩니다 (SOT §6.6 H-9a).
- 주관기관은 다른 기관을 주관으로 먼저 지정하기 전에는 삭제되지 않습니다 (SOT §6.6 H-8). 기관을 지우면 소속 인력의 기관은 비게 됩니다.
- 인력을 삭제하면 담당 작업·마일스톤·리스크·PM 지정·실적 참여자·회의 참석자 같은 참조가 함께 정리됩니다. 대화상자에서 건수를 확인하세요 (SOT §6.6 H-9).
- PM은 과제당 1명입니다. 다른 사람을 PM으로 지정해도 기존 PM은 자동으로 바뀌지 않고 경고만 뜹니다 (SOT §7.10).
- 참여율(%)은 여기에 없습니다. 연차마다 다르므로 연구비 화면의 산출근거에서 입력합니다 (SOT §5.11).
